### 2. Bugs found and fixed this run (all pushed to main, all built, all retested)

1. **gpu-screen-recorder 6.0.0-1 -> 6.0.0-2** (commit f4ebb74) - the spec ran
   `setcap cap_sys_admin+ep` on gsr-kms-server from `%post`, mutating the file
   after rpm recorded its metadata. **Every install left the package failing
   verification forever**: `rpm -V gpu-screen-recorder` -> `........P
   /usr/bin/gsr-kms-server` (rc=1). Fixed by declaring the capability in
   `%files` with `%caps(cap_sys_admin=ep)` so rpm applies and tracks it itself;
   dropped the now-unneeded `Requires(post): libcap`.
   AFTER: `rpm -V` clean, `getcap` still `cap_sys_admin=ep`, zero scriptlets.
2. **gpu-screen-recorder -2 -> -3** (commit 692ec28) - the 16 helper scripts in
   `%{_datadir}/gpu-screen-recorder/scripts` call **xdotool** (5 scripts),
   **pactl** (list-sinks.sh) and **ffmpeg** (twitch-stream-local-copy.sh);
   nothing pulled any of them in. Added as Recommends (+turbojpeg, which
   src/image_writer.c dlopen()s for JPEG screenshots).
3. **hyprland-contrib -2 -> -3** (commit 3e0c9cf) - `scratchpad:8` hardcodes
   `_menu_cmd="rofi -dmenu -i -p scratchpad"` as the window picker used by
   -g/-l (scratchpad:128) and killed by -g (scratchpad:101), but **rofi was
   nowhere in the spec**. `dnf install scratchpad` then left the picker
   non-functional. Added `Recommends: rofi` (Recommends, not Requires, because
   -m overrides the menu program).
4. **logseq 2.0.1-2 -> 2.0.1-3** (commit f35e554) - two different `%changelog`
   entries both claimed `2.0.1-2`; git (89a9846) shows the Aug 05 entry shipped
   while Release was still 1. Merged the two same-day -1 entries. logseq was
   the ONLY spec of 56 with this defect.
