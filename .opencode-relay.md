### 2. Bug found and fixed this run

1. **extension-manager: bogus `%changelog` date** (commit 588f707) - the
   `0.6.5-2` entry read `* Mon Aug 04 2026`, but **2026-08-04 is a Tuesday**
   (`date -d 2026-08-04 +%A` -> Tuesday; the commit that added it, d1a81ec, is
   dated 2026-08-04). rpm/rpmlint flagged it:
   BEFORE: `W: specfile-warning warning: bogus date in %changelog: Mon Aug 04
   2026 ... - 0.6.5-2`

   time, so the already-shipped RPM records `Tue Aug 04 2026` (verified with
   `rpm -q --changelog extension-manager` on the installed 0.6.5-2 from COPR).
   The defect is source-only; bumping Release would be pure churn with no
   user-visible change. This is the correct reading of RELEASE REVISION
   DISCIPLINE (b): nothing users receive changed.
   COPR still rebuilt it (10837791, succeeded) because the spec changed.
